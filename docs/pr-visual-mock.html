Rule 1 — the bot never hides a change. The comment is a layer over the net migration diff, never a curation of it: every AddField, RenameField, RemoveField must appear in both the summary and the diagram. Omission is only allowed as an explicit count ("2 more changes — expand"), never as silence. This is enforced in CI — a test asserts each operation from the diff is present in the generated comment, so a dropped fact fails the build instead of quietly misleading a reviewer.

Rendering notes found the hard way: (1) Mermaid's htmlLabels accept real <table> markup — bgcolor and align survive its DOMPurify sanitizer, so left-aligned keys, right-aligned types, and per-row colors all work natively in the diagram. Caveat: GitHub renders Mermaid with its own sanitizer — verify once with a real PR comment. (2) If using classDef anywhere, style names must be lowercase — camelCase names are silently dropped, no error, no color. (3) In classDiagram specifically, classDef styling is unreliable — use flowchart.
